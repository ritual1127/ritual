## 1. 정해 둔 것 (바꾸려면 첫 업로드 전에)

| 항목 | 정한 값 | 이유 |
|---|---|---|
| 방식 | TWA(Trusted Web Activity) + Bubblewrap | 구글 공식 방식. 웹 그대로, 앱 용량 1MB, 웹 고치면 앱도 반영 |
| 패키지 이름 | `io.github.ritual1127.seongjeok` | **한 번 올리면 영영 못 바꿈.** 내가 가진 GitHub 주소를 뒤집은 이름이라 겹칠 일이 없고, 'naver'를 넣지 않아 상표 문제를 피함 |
| 스토어 이름 | 성적계산기 - 수행평가·내신등급·학점 | 검색어를 이름에 넣음. 언제든 바꿀 수 있음 |
| 계정 종류 | 개인 | 사업자 계정은 D-U-N-S 번호가 필요한 대신 '12명 14일 테스트'가 면제됨 |
| 광고 | 애드센스 유지 | 구글이 TWA 안 애드센스를 허용함 |
| 대상 연령 | 13세 이상 | 13세 미만을 넣으면 가족 정책 때문에 애드센스를 못 씀 |

## 3. 이미 만들어 둔 것

저장소 브랜치 `feat/android-app`에 있다.

**웹(사이트) 쪽**
- 앱 정보 파일 `manifest.json`: 설명, 언어, 분류, 테마 아이콘, 바로가기 4개(목표점수·내신등급·학점·급식)
- 아이콘 `icons/`: 안드로이드 13 테마 아이콘, 바로가기 아이콘 4개
- 오프라인 화면 `offline.html` + 서비스워커 `app-sw.js`: 인터넷이 끊겨도 공룡 화면 대신 담아 둔 계산기·안내 화면
- AI 답변 신고 버튼: 구글 플레이 생성형 AI 정책 필수 항목. 답 아래 '답변 신고' → 앱 안 문의하기
- 개인정보처리방침 7번 '안드로이드 앱' 항목
- 앱 안내 카드(안드로이드 브라우저에서만, 출시 후 켬)
- `_config.yml`: 앱 인증 파일 폴더(.well-known)는 사이트에 올리고, android·store 폴더는 안 올림

**앱 쪽**(`android/`)
- `twa-manifest.json`: 앱 설정(targetSdk 36 = 2026년 8월 31일 이후 신규 앱 필수 기준 충족)
- 안드로이드 프로젝트: 서명 없이 빌드해서 컴파일되는 것까지 확인함
- `build-release.ps1`: 업로드 키 만들기 → 빌드 → 서명 → assetlinks.json 생성까지 한 번에(시험용 키로 끝까지 실행해 봄)
- `README.md`: 빌드·업데이트·문제 해결

**스토어 쪽**(`store/`)
- 그래픽: 아이콘 512, 그래픽 이미지 1024×500, 스크린샷 6장(1080×1920)
- `listing-ko.md`: 앱 이름·간단한 설명·자세한 설명·새 기능
- `app-content.md`: 앱 콘텐츠 답안(데이터 보안, 콘텐츠 등급, 타겟층, 광고, AI)
- `testers.md`: 테스터 모집 문구·14일 운영·프로덕션 신청 답변 예시
- `growth-plan.md`: 사용자 유입 계획

## 4. 단계별 진행

### 4-1. 개발자 계정 만들기
- [ ] https://play.google.com/console 가입 → 계정 유형 '개인'
- [ ] 등록비 결제, 본인 인증(신분증), 연락처·전화번호 인증
- [ ] Play Console 앱으로 실제 안드로이드 기기 확인을 요구하면 따라 하기
- 인증은 보통 1~3일, 길면 더 걸린다. **오늘 신청해 두기.**

### 4-2. 출시 전 보안 정리
- [ ] 관리자 PIN 교체. 예전 PIN이 공개 저장소 기록에 남아 있다. 앱으로 사용자가 늘기 전에 바꾼다.
  - 명령: `cd feedback-api` → `npx wrangler secret put ADMIN_PIN` (새 PIN 8자리 이상)

### 4-3. 사이트 변경 배포
- [ ] `feat/android-app` 브랜치를 main에 합쳐 배포(아이콘·매니페스트·오프라인·AI 신고·개인정보처리방침)
- [ ] 배포 확인: `https://naver1.cloud/manifest.json`, `https://naver1.cloud/icons/monochrome-512.png`

### 4-4. 앱 빌드
- [ ] PowerShell: `cd android` → `.\build-release.ps1`
- [ ] 처음 실행하면 업로드 키(`upload-key.jks`)를 만든다. **비밀번호와 키 파일을 두 군데 이상 백업.**
- [ ] 결과: `app-release.aab`(Play에 올림), `app-release-signed.apk`(폰에 직접 설치 확인용)

### 4-5. Play Console 앱 만들기 + 스토어 등록정보
- [ ] 앱 만들기: 앱 이름, 기본 언어 한국어, 앱, 무료, 선언 체크
- [ ] 스토어 등록정보: `store/listing-ko.md` 붙여 넣기, `store/graphics/` 업로드(아이콘·그래픽 이미지·스크린샷 1~6 순서)
- [ ] 카테고리 '교육', 연락처 이메일·웹사이트

### 4-6. 앱 콘텐츠(정책) 작성
`store/app-content.md` 보고 그대로 입력
- [ ] 개인정보처리방침 URL
- [ ] 앱 액세스 권한(로그인 없음)
- [ ] 광고 있음 / 광고 ID 사용 안 함
- [ ] 콘텐츠 등급 설문(예상: 전체이용가)
- [ ] 타겟층: 13~15, 16~17, 18세 이상
- [ ] 데이터 보안 양식
- [ ] 정부·금융·건강·뉴스: 해당 없음
- [ ] 애드센스 자동 광고의 전면(비네트) 광고 끄기 권장

### 4-7. 내부 테스트로 내 폰에서 확인
- [ ] 테스트 및 출시 > 내부 테스트 > 새 버전 > `app-release.aab` 업로드
- [ ] 처음 올리면 'Play 앱 서명' 사용에 동의(필수)
- [ ] 테스트 및 출시 > 설정 > 앱 무결성 > **앱 서명 키 인증서 SHA-256** 복사
- [ ] `.\build-release.ps1 -PlayFingerprint "복사한 값"` → 생긴 `.well-known/assetlinks.json`을 커밋·배포
- [ ] 내 폰에 내부 테스트 앱 설치: **위쪽 주소창이 없어야 정상**. 주소창이 보이면 `android/README.md`의 '주소창이 보여요' 참고
- [ ] 확인: 계산 5종, 바로가기(아이콘 길게 누르기), 급식 알림 켜기(알림 권한), 오프라인(비행기 모드), 다크 모드, AI 도우미·답변 신고

### 4-8. 비공개 테스트 12명 × 14일
`store/testers.md` 참고
- [ ] 구글 그룹 만들기 → 비공개 테스트 트랙에 그룹 추가 → 같은 AAB로 출시
- [ ] 참여 링크를 테스터 15명 이상에게 보내기(모집 문구 있음)
- [ ] 12명 이상 유지 확인(빠지면 14일이 다시 시작된다는 사례가 많다)
- [ ] 3일·10일째 작은 미션, 7일째 의견 정리·수정(웹만 고치면 앱에 바로 반영)

### 4-9. 프로덕션 액세스 신청 → 정식 출시
- [ ] 14일이 지나면 대시보드의 '프로덕션 액세스 신청' → 테스트 경험 질문 답하기(`testers.md`에 예시)
- [ ] 승인되면 프로덕션 트랙에 출시 → 검토(보통 며칠, 최대 7일 안팎)
- [ ] 국가: 대한민국(원하면 전체)

### 4-10. 출시 당일
- [ ] `site-nav.js`의 `const PLAY_ID = ''`에 패키지 이름 넣고 배포: 안드로이드 브라우저 방문자에게 앱 안내 카드가 뜬다
- [ ] 푸터 '안드로이드 앱' 링크, 사용법 안내에 앱 단계 추가
- [ ] AI 도우미 지식에 앱 설치 답 추가 → `npm run build:kb` → 배포 → /admin '지금 색인하기'
- [ ] 홍보 시작(5번)

## 5. 사용자 유입

자세한 내용은 `store/growth-plan.md`

- **스토어 최적화**: 이름·설명에 검색어, 스크린샷 첫 3장에 핵심 장점, 첫 주 리뷰 20개 목표(조작 말고 부탁)

- **채널**: 카톡 단톡방, 인스타·쇼츠 15초 화면 녹화, 블로그 계산법 글, 고등학생·대학생 커뮤니티(규칙 지키기), 학교 QR 포스터

## 6. 출시 후 관리

- 웹을 고치면 앱도 바로 바뀐다. 앱을 다시 올릴 일은 아이콘·이름·바로가기·targetSdk를 바꿀 때뿐이다.
- 다시 올릴 때: `twa-manifest.json`에서 `appVersionCode`를 +1 → `bubblewrap update` → `.\build-release.ps1` → 업로드
- 해마다 8월 말쯤 목표 API 수준이 오른다(2027년 Android 17 예상). 7월에 Bubblewrap 업데이트 → 다시 빌드
- 리뷰에는 48시간 안에 답하기, Android vitals(비정상 종료) 주 1회 확인

## 7. 자주 막히는 것

| 증상 | 원인 | 해결 |
|---|---|---|
| 앱 위에 주소창이 보임 | 사이트 인증(assetlinks) 실패 | Play 앱 서명 키 지문을 넣었는지, `/.well-known/assetlinks.json`이 열리는지 확인 |
| 빌드가 "non-ASCII characters"로 멈춤 | 경로에 한글 | `build-release.ps1`이 영문 경로로 복사해서 빌드함 |
| `bubblewrap build`가 "androidSdk isn't correct" | 안드로이드 스튜디오 SDK에 tools 폴더 없음 | `build-release.ps1` 사용 |
| 급식 알림이 안 옴 | 안드로이드 13 이상 알림 권한 거부 | 앱 설정 > 알림 허용 |
| 프로덕션 신청 버튼이 안 눌림 | 테스터 12명·14일 미충족 | 테스터 수 확인, 기간 다시 확인 |
| 심사 거절: 메타데이터 | 설명에 같은 단어 반복, 다른 앱·브랜드 언급 | 설명 문구 정리 |
| 심사 거절: 기능 부족(웹뷰 앱) | 단순 웹 포장으로 판단 | 오프라인·알림·바로가기 등 앱 기능 강조, 재심사 요청 |
