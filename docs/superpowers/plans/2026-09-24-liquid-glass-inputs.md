# 직관적인 입력 + 애플식 리퀴드 글래스 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 작성자가 이 세션에서 직접 실행한다(사용자는 A안과 "검증 후 바로 배포"를 골랐다).

**Goal:** 입력칸과 조작부가 한눈에 보이게 바꾸고, 휴대폰은 입력 먼저와 하단 유리 결과 바 구조로 재구성하고, 애플식 리퀴드 글래스(굴절·반사)를 떠 있는 조작부에 적용해 naver1.cloud에 배포한다.

**Spec:** `docs/superpowers/specs/2026-09-24-liquid-glass-inputs-design.md`

## Global Constraints
- 기능, URL, SEO 메타, 저장 키, 롤링·도장·축하 모션은 유지한다. `npm test` 통과, SEO 100/100.
- 새 라이브러리는 없다. 굴절은 크로미움에서만 켜고, 나머지 브라우저는 흐림 유리를 쓴다.
- 파랑은 조작, 형광펜은 결과, 초록은 맞음, 빨강은 문제에만 쓴다.

## Review Focus
1. 결과 바: 결과가 없을 때 숨는지, 큰 숫자가 보일 때 숨는지, 누르면 결과 카드로 가는지, 데스크톱에서는 뜨지 않는지.
2. 결과 바가 마지막 내용(푸터)과 포커스된 입력칸을 가리지 않는지(아래 여백, `scroll-padding-bottom`).
3. 굴절 필터 크기가 요소 크기를 따라가는지(알림 폭 변화, 화면 회전).
4. 사파리·파이어폭스 경로: `--lens`가 비면 `backdrop-filter`가 흐림만으로 유효한지.
5. DOM 순서가 바뀐 뒤 Enter로 다음 칸 이동, 초기화·되돌리기, 축하 도장이 그대로 동작하는지.

### Task 1: 콘텐츠
- 개인정보처리방침 수정: 좋아요/싫어요 항 삭제, 광고 항을 애드센스 기준으로 수정, 번호 재정렬, 시행일자 변경.
- 수행·지필에서 빠른 선택 카드와 `applyPreset`, 프리셋 표시 코드를 삭제한다. `calc-core.js`의 `splitWeights`와 그 테스트도 삭제한다.
- 사용법 문구 수정. 결과 바에 맞게 미니 결과 문자열에서 접두어를 뺀다.

### Task 2: 마크업 재구성(계산기 5곳)
- 결과 카드를 입력 폼 뒤로 옮긴다. 초기화 버튼은 페이지 제목 줄로 옮긴다.
- 입력 구역에 `step` 클래스를 붙인다(번호 원 표시용).
- 뷰포트 메타에 `interactive-widget=resizes-content`를 추가한다(안드로이드 키보드 위에 결과 바).

### Task 3: 스타일
- 새 토큰, 입력 상자, 세그먼트, 스테퍼, 추가 버튼, 결과 카드, 합계 카드, 표, 글·허브·NEIS 페이지를 만든다.
- 글래스(A)와 결과 바, 2단/1단 레이아웃을 만든다.

### Task 4: 공용 스크립트
- 캡슐 미니 결과를 하단 결과 바로 바꾼다(IntersectionObserver 대상은 `.result-main`, `inert` 처리).
- 굴절 필터 생성기 `lens(el)`(크로미움만, ResizeObserver)를 캡슐, 메뉴, 결과 바, 알림에 적용한다.

### Task 5: 검증
- QA 스위트를 갱신하고, 결과 바·굴절 전용 검사를 추가하고, 스크린샷으로 확인한다.

### Task 6: 배포
- `?v=`를 올리고 main에 fast-forward한 뒤 push한다. 라이브 해시와 스모크 테스트를 확인한다.
