# 성적표 사진 OCR 자동입력 설계

## 배경

`index.html`의 점수 입력 화면에서 사용자가 매 학기 수행평가·지필고사 점수를 손으로 하나씩 입력해야 한다. 실제 성적표(나이스 표준 양식) 사진을 첨부하면 자동으로 점수를 채워주는 기능을 추가한다.

실제 성적표 샘플(사용자 제공, 아래 실제 캡처 기준)의 행 구조:

```
[과목(병합, 첫 행에만)] [구분: 지필/수행] [항목명(비율%)] [만점] [받은점수] [원점수합계] [성취도(수강자수)] [원점수/과목평균(표준편차)]
```

예: `역사 | 지필 | 1회고사(20.00%) | 100.00 | 97.00 | ... `, `역사 | 수행 | NIE 포트폴리오(30.00%) | 100.00 | 100.00 | ...`

**중요 제약 발견**: 이 앱은 항목 라벨을 사용자가 직접 짓지 않고 `수행1`/`수행2`/`중간고사`/`기말고사`처럼 시스템이 자동 부여한다(`index.html`의 `modalConfigFromCounts`, `examLabel` 참고). 성적표의 실제 항목명("NIE 포트폴리오", "1회고사")과는 텍스트가 겹치지 않으므로, **항목 단위 매칭은 항목명 텍스트가 아니라 "구분(지필/수행) + 사진 내 등장 순서 + 비중(%)"으로 한다.** 과목명은 사용자가 직접 지어 `localStorage`의 `subjectDrafts`에 이름으로 저장돼 있으므로(`subjectDrafts[과목명]`), 과목명은 텍스트로 매칭 가능하다.

## UI

- 점수 입력 화면(`renderScoreInputs()`가 그리는 `#inputs` 박스) 상단, 과목명 제목 아래에 "📷 사진으로 채우기 (베타)" 버튼 추가.
- 클릭 시 `<input type="file" accept="image/*" capture="environment">`를 트리거해 카메라 촬영 또는 갤러리 선택.
- 이미지 선택 후 모달에 "인식 중..." 스피너 표시.
- 인식 완료 후 **검토 모달**을 띄운다: 매칭된 (구분 + 순서 → 등록된 항목 라벨) 목록을 편집 가능한 점수 입력창으로 보여줌. 등록 개수와 인식 개수가 다르면 상단에 "등록 N개 / 인식 M개 — 순서대로 매칭했어요, 확인해주세요" 경고 배너.
- "적용" 버튼 클릭 시 실제 `s${i}`/`t${i}` 인풋에 값 반영 (기존 `sanitizeScoreInput` 통과).
- "취소" 시 아무 것도 반영하지 않음.

## OCR 파이프라인

- **엔진**: Tesseract.js를 jsDelivr CDN에서 버튼 최초 클릭 시점에 동적 `<script>` 로드 (`https://cdn.jsdelivr.net/npm/tesseract.js@5/dist/tesseract.min.js`). 초기 페이지 로드에는 영향 없음.
- **언어**: `kor+eng` (숫자와 한글 혼합이라 영어 학습데이터도 필요 — `%`, 소수점 숫자 인식에 도움).
- **실행**: `Tesseract.recognize(file, 'kor+eng')` → `result.data.text` (줄바꿈 포함 원문 텍스트) 사용. 표 형태라 각 행이 대체로 한 줄에 대응한다고 가정.

## 매칭 알고리즘

1. OCR 텍스트를 줄 단위로 분리.
2. 각 줄에서 정규식으로 다음을 추출 시도:
   - 구분: 줄에 `지필` 또는 `수행` 포함 여부
   - 비중: `\((\d+(?:\.\d+)?)\s*%?\)` 패턴으로 괄호 안 숫자 추출
   - 점수 후보: 줄에서 발견되는 모든 `\d{1,3}(\.\d+)?` 숫자 중, 100 이하이고 문맥상 "만점(주로 100.00)" 다음에 오는 마지막 숫자를 "받은점수"로 채택 (같은 줄에 100.00이 두 번 나오면 뒤의 값을 점수로, 앞의 값을 만점으로 취급 — 만점이 100이 아닌 경우엔 첫 숫자를 만점, 다음 숫자를 점수로 취급하고 필요시 100점 환산은 하지 않고 원점수 그대로 사용)
   - 과목명 후보: `지필`/`수행`/괄호/숫자를 포함하지 않는 순수 한글 줄은 과목명 줄로 간주해 "현재 과목 컨텍스트"로 기억.
3. 현재 열려있는 과목(`selectedSubject`)과 이름이 일치(공백 제거 후 완전일치, 안 맞으면 부분포함)하는 과목 컨텍스트 구간의 줄만 사용. 과목명 줄이 아예 인식되지 않았다면(사진에 한 과목만 있는 경우) 전체를 그 과목 것으로 간주.
4. 구분별로 등장 순서대로 리스트를 만들어 등록된 `currentCfg.performances`/`currentCfg.exams`의 같은 순서 항목에 매핑. 개수가 다르면 짧은 쪽 길이까지만 자동 매칭, 나머지는 검토 모달에서 공란.
5. 비중(%)이 추출됐고 등록된 항목 비중과 ±1%p 이내로 다르면 검토 모달에 "⚠️ 비중이 등록값과 달라요 (사진 20% / 등록 25%)" 힌트만 표시 (막지는 않음 — 학기 중 비중 변경 가능성 때문).

## 에러 처리

- Tesseract CDN 로드 실패(오프라인 등): "OCR 엔진을 불러오지 못했어요. 인터넷 연결을 확인하거나 직접 입력해주세요."
- 텍스트를 전혀 못 읽음(빈 결과): "사진에서 글자를 인식하지 못했어요. 더 밝은 곳에서 정면으로 다시 찍어보세요."
- 매칭된 항목이 0개: 검토 모달 대신 바로 위 실패 메시지와 동일하게 안내.

## 테스트

자동화 테스트 없음(정적 사이트). 수동 확인 체크리스트:

- [ ] 실제 성적표 사진(제공된 샘플과 유사한 나이스 양식)으로 지필 2개 + 수행 3개가 등록된 과목에서 순서대로 정확히 매칭되는지
- [ ] 등록 개수와 사진 인식 개수가 다를 때 경고 배너가 뜨는지
- [ ] 검토 모달에서 값 수정 후 "적용"하면 실제 입력창에 반영되는지
- [ ] "취소" 시 기존 입력값이 그대로인지
- [ ] 사진에 여러 과목이 찍혀 있을 때 현재 선택된 과목명과 일치하는 블록만 쓰는지
- [ ] 흐릿한 사진/글자 없는 사진에서 실패 안내가 뜨는지
- [ ] 오프라인 상태에서 CDN 로드 실패 안내가 뜨는지

## 범위 밖

- 항목명 텍스트 기반 매칭 (라벨 자체가 시스템 자동생성이라 애초에 불가능 — 위 배경 참고).
- 사진으로 새 과목을 자동 등록(수행/지필 개수·비중 설정)하는 기능 — 이번 스펙은 "이미 등록된 과목의 점수 채우기"까지만. 등록 자동화는 별도 요청 시 추후 검토.
- 손글씨 성적표 인식 — 인쇄된 표 기준으로만 설계.
