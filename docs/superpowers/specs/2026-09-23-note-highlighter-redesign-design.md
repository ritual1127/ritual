# 사이트 전면 리디자인 — "노트 & 형광펜" 설계

## 배경

기존 디자인은 페이지마다 따로 덧대어져 왔다. `styles.css`(52KB)에 이미 사라진 기능(그래프·시뮬레이션·AI 분석) 스타일이 남아 있고, `site-nav.js`는 페이지가 뜬 뒤 블로그/글 구조를 JS로 뜯어고친다. 계산기는 전부 "값 입력 → 버튼 → 결과"여서 결과를 보려면 매번 버튼을 눌러야 하고, 오류는 `alert()`나 결과 자리의 빨간 문구로만 알려준다.

요청은 **기존 디자인은 버리고 기능만 유지한 채, 편의성과 직관성 중심으로 새로 만드는 것**이다.

## 확정된 결정

- 톤: **노트 & 형광펜**. 크림색 종이 배경, 잉크 네이비 글자, 핵심 숫자에는 라임 형광펜을 칠한다.
- 범위: 사이트 전체 21페이지(계산기 5개, 급식·시간표, 가이드 허브와 글 10개, FAQ·사용법·개인정보).
- 유지: URL, `<head>` SEO 메타(title/description/canonical/og/JSON-LD), GTM·AdSense 스크립트, localStorage 키(`rankRows`, `rankSystem`, `gpaRows`, `gpaScale`, `theme`, `neisSchool`, `neisClass`, `neisTimetableMode`), NEIS 프록시·푸시 API.
- 기술: 정적 HTML/CSS/JS를 유지한다. 프레임워크나 빌드 도구는 추가하지 않는다. 외부 리소스는 Pretendard 웹폰트(jsDelivr) 하나만 추가한다.
- 진행: 사용자가 "끝까지 자동 진행"을 선택했다. 새 브랜치에서 구현하고 검증한다. push와 PR은 하지 않는다.

## UX 원칙

1. **실시간 계산.** 계산 버튼이 없다. 입력할 때마다 결과가 바로 바뀐다.
2. **결과를 먼저 보여준다.** 모바일에서는 결과 카드가 입력보다 위에 있다. 스크롤해서 입력칸으로 내려가도 상단바에 작은 결과 표시가 떠서 결과가 계속 보인다. 데스크톱에서는 입력이 왼쪽, 결과가 오른쪽에 붙어 따라온다.
3. **오류 대신 안내.** "비율 합계 90% · 10% 더 필요", "빈칸 2개 남음"처럼 다음에 할 일을 알려준다. `alert()`는 없앤다. 범위를 벗어난 입력은 해당 칸에 표시하고(`aria-invalid`), 포커스를 벗어나면 min~max로 보정한다.
4. **다음 행동 제시.** 예: "A까지 3.5점", 목표점수 계산기의 등급별 필요 점수 표, "100점을 받아도 최종 88.6점".
5. **빠른 입력.** 숫자 칸에서 Enter를 누르면 다음 칸으로 이동한다. 포커스하면 값이 전체 선택된다. `inputmode`는 적절히 지정하고, iOS 자동 확대를 막기 위해 입력 글자 크기는 16px 이상으로 한다.
6. **다시 와도 그대로.** 수행·지필과 목표점수 입력도 localStorage에 저장한다. 입력을 저장하는 계산기 4개(수행·지필, 목표점수, 내신등급, 학점)에 "초기화" 버튼을 둔다. 초기화는 두 번 눌러야 실행되며 모달은 쓰지 않는다. GPA 환산은 칸이 3개뿐이라 저장하지 않는다.

### 모티프

- **점 격자 배경**: 불릿저널처럼 옅은 점 격자(`radial-gradient`, 24px 간격)를 깐다.
- **형광펜**: 결과 숫자, 로고의 "성적", 선택된 도구 칩에 쓴다. 약간 기울어진 둥근 띠(`::before`)로 그리고, 결과가 처음 나올 때만 왼쪽에서 오른쪽으로 칠해지는 애니메이션(250ms)을 넣는다.
- **밑줄 입력칸**: 빈칸 채우기처럼 `--sunk` 배경에 2px `--ink-3` 밑줄을 긋는다(비텍스트 대비 3:1 이상). 포커스하면 `--hl-soft` 배경과 `--primary` 밑줄로 바뀌어서 지금 쓰는 칸이 형광펜으로 칠한 것처럼 보인다.
- **괘선 행**: 입력 행과 급식 메뉴, 시간표 교시는 노트 괘선처럼 가는 선으로 나눈다.
- 이모지 아이콘은 쓰지 않는다. 아이콘은 모두 인라인 SVG(해/달, 화살표, 닫기, 종)다.

### 타이포

- Pretendard Variable 동적 서브셋(`cdn.jsdelivr.net/npm/pretendard@1.3.9/.../pretendardvariable-dynamic-subset.min.css`)에 `preconnect`를 걸어 쓴다. 폴백은 `-apple-system, "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif`.
- 본문 16px, 줄간격 1.6. 크기 단계는 12 / 14 / 16 / 18 / 22 / 28(h1) / 56(결과 숫자).
- 숫자는 모두 `font-variant-numeric: tabular-nums`. 결과 숫자는 800 weight, 자간 -0.03em.

### 모션

모션은 150~250ms, `ease-out`만 쓴다. 형광펜 칠하기, 진행바 마커 이동, 칩/버튼 눌림(`scale .97`)이 전부다. `prefers-reduced-motion`이면 모두 끈다.

## 공통 셸

모든 페이지가 같은 정적 마크업을 쓴다. JS로 주입하지 않으므로 레이아웃이 밀리지 않고, 크롤러도 링크를 바로 읽을 수 있다.

```
<a class="skip-link" href="#main">본문 바로가기</a>
<header class="appbar">           ← sticky, 56px
  <a class="logo">성적계산기</a>  ("성적"에 형광펜)
  [미니 결과 pill — 계산기 페이지에서 결과 카드가 화면 밖일 때만]
  <button class="theme-toggle">   (SVG 해/달, aria-label)
</header>
<nav class="toolnav" aria-label="도구">   ← 스크롤되면 사라짐
  수행·지필 · 목표점수 · 내신등급 · 학점 · GPA 환산 | 급식 · 시간표
  (현재 페이지는 aria-current="page", 형광펜 배경. 모바일은 가로 스크롤과 양끝 페이드)
</nav>
<main id="main"> … </main>
<footer class="site-footer"> 안내 문구 · 계산 가이드 · FAQ · 사용법 · 개인정보처리방침 · © </footer>
```

`site-nav.js`는 새로 쓰고 역할을 아래로 줄인다.

1. **테마**: `<head>`에서 동기로 실행해 저장된 테마를 첫 페인트 전에 적용한다. 저장값이 없으면 시스템 설정을 실시간으로 따른다. 토글하면 저장한다.
2. **도구 칩**: 로드할 때 현재 칩이 가운데 오도록 가로 스크롤 위치를 직접 계산한다. 세로 스크롤은 건드리지 않는다.
3. **서비스워커 등록**(`/app-sw.js`): #6에서 빠진 등록을 복구해 급식 알림을 살린다.
4. **입력 보조**: Enter로 다음 칸 이동, 포커스 시 전체 선택, blur 시 min~max 보정.
5. **전역 헬퍼 2개**:
   - `setMiniResult(text)`: 미니 결과 pill 내용을 바꾸고, 스크린리더용 `aria-live` 문장은 600ms 디바운스로 갱신한다. 빈 문자열이면 숨긴다. pill은 `.result-card`가 IntersectionObserver 기준으로 화면 밖일 때만 보인다.
   - `armReset(button, action)`: 첫 탭에서는 "한 번 더 누르면 초기화"로 바뀌고, 3초 안에 다시 누르면 실행한다.

없애는 것: 숫자 칸 ± 스테퍼 주입, 블로그 허브·글 레이아웃의 런타임 재구성, 설명 섹션 치환, 피드백 위젯 처리.

### 레이아웃

- 페이지 폭은 모바일 16px 거터, 최대 1080px. 글 페이지 본문은 최대 720px.
- 계산기는 `.calc` 그리드를 쓴다. DOM 순서는 결과 카드가 먼저다(모바일 시각 순서와 같음). 960px 이상에서는 `grid-template-areas`로 입력은 왼쪽 `1fr`, 결과는 오른쪽 360px에 `sticky`로 둔다.
- 계산기 아래에는 설명 섹션("계산 방법")을 정적으로 둔다. 기존 SEO 문장과 FAQ `details`를 유지하고 해당 가이드 글 링크를 붙인다.
- AdSense 자동광고가 그리드 안에 들어와도 깨지지 않도록 `.calc > .google-auto-placed { grid-column: 1 / -1 }`를 둔다.

## 페이지별 설계

### 수행·지필 (`/`)
- 입력 카드: "수행평가"와 "정기고사" 두 그룹. 그룹 헤더에 개수 스테퍼(− n +, 0~10)를 둔다. 행은 `n번 | [점수 점] | [비율 %]`.
- 카드 하단에 **비율 미터**: 합계 바와 "반영비율 합계 90% · 10% 더 필요 / 100% ✓ / 110% · 10% 초과".
- 결과 카드 상태:
  - 평가 0개: "수행평가나 정기고사를 1개 이상 추가해 주세요"
  - 범위 밖 값: "점수와 비율은 0~100 사이로 입력해 주세요"
  - 점수 미입력: "—" + "점수를 입력하면 바로 계산돼요"
  - 일부 입력: 라벨을 "지금까지 반영된 점수"로 바꾸고, 형광펜 없는 흐린 숫자 + "빈칸 n개"
  - 점수는 다 입력했지만 비율 ≠ 100: "반영비율 합계를 100%로 맞춰 주세요 (현재 n%)"
  - 완료: 형광펜을 칠한 최종점수, 등급 배지, 0~100 진행바(60/70/80/90 눈금과 마커), "A까지 3.5점" 또는 "A등급 달성", `details` "계산식 보기"(`92×20% + …`)
- 미니 결과: 완료면 "86.5점 · B", 일부 입력이면 "반영 45.2점".
- 저장 키: `scoreCalc` = `{performance:[{score,weight}], exam:[…]}`. 기본값은 2+2개, 비율 20/20/30/30.

### 목표점수 (`/target-score/`)
- 목표: 세그먼트 [점수로 | 등급으로]. 점수로는 숫자 칸 하나, 등급으로는 큰 A~E 버튼(`aria-pressed`)과 기준 문구.
- "지금까지 본 평가" 행: 이름, 점수, 비율, 삭제 버튼. "+ 평가 추가" 버튼. 점수와 비율이 둘 다 빈 행은 계산에서 무시하고, 하나만 빈 행은 "빈칸을 채워 주세요"로 안내한다.
- "앞으로 볼 시험": 이름과 비율. 그리고 비율 미터.
- 계산식: `필요 = (목표 − Σ점수×비율/100) × 100 ÷ 남은비율`. 곱셈을 먼저 해서 부동소수 오차를 줄이고, 표시값은 소수 둘째 자리에서 올림한다(ε 보정). 필요 점수를 덜 보여주면 안 되기 때문이다.
- 결과: 큰 숫자 "97.5점"과 "기말고사에서 97.5점 이상". 이미 달성했으면 "0점을 받아도 최종 X점", 불가능하면 빨간 숫자와 "100점을 받아도 최종 X점". 남은 비율이 0%면 따로 안내한다. 그 아래 **등급별 필요 점수 표**(A~D: 필요 점수 / "달성" / "불가")를 두고 선택한 등급 행을 강조한다.
- 저장 키: `targetCalc` = `{mode, target, grade, completed:[{name,score,weight}], remaining:{name,weight}}`. 기본값은 수행평가 90/30, 중간고사 80/30, 기말고사 40%.

### 내신등급 (`/rank/`)
- 세그먼트 [9등급제 | 5등급제].
- 과목을 카드 한 장씩 입력한다. 1행은 과목명과 삭제, 2행은 단위수·수강자·석차·동점자 4칸(라벨 위). 카드 오른쪽 위에 실시간 칩 "4.00% · 1등급"을 표시하고, 잘못된 조합은 카드 안에 인라인 오류로 알린다.
- 결과: 단위수 가중 평균 등급(큰 숫자), "단위수 합 n · 과목 n개 · 9등급제", 과목별 표.
- 등급 구간은 칩 그리드("1등급 ~4% · 4%")로 보여주고 평균 등급 구간을 강조한다.
- 저장은 기존 키와 기존 형식(`rankRows`, `rankSystem`)을 그대로 써서 사용자 데이터가 유지된다.

### 학점 (`/gpa/`)
- 세그먼트 [4.5 | 4.3 | 4.0] 만점. 과목 행은 이름, 학점, 성적(네이티브 `select`), 삭제.
- 결과: "3.90 / 4.5", "총 이수 n학점 · 평점 반영 n학점 · 만점 대비 n%", 과목별 평점 표, 평점표 칩.
- 만점 기준을 바꿀 때 새 기준에 없는 등급(`A-` 등)은 `A0`처럼 같은 알파벳의 기본 등급으로 옮긴다. 기존에는 A+로 바뀌던 문제를 고친다.
- 저장: 기존 키와 형식(`gpaRows`, `gpaScale`)을 유지한다.

### GPA 환산 (`/gpa-converter/`)
- 현재 GPA, 현재 만점, 변환할 만점. 만점 칸 아래에 빠른 선택 칩(4.5/4.3/4.0)을 둔다(datalist 대체).
- 결과: "3.63 / 4.3"과 두 만점의 비율 막대(같은 %), 참고용 주의 문구.

### 급식 (`/todayfood/`)
- 학교 선택기(공통): `<form>` 검색으로 Enter가 기본 동작한다. 결과는 `<button>` 목록이라 키보드로 접근할 수 있다. 선택한 학교는 카드로 보여주고 링크 공유와 학교 변경 버튼을 둔다.
- 날짜: ‹ 날짜 › 와, 오늘이 아닐 때만 보이는 "오늘" 버튼. 조식·중식·석식 세그먼트(기본값은 현재 시각 기준).
- 메뉴는 괘선 목록. 로딩, 없음, 실패를 각각 안내한다.
- 알림: 스위치형 버튼(`aria-pressed`)과 설명. SW 등록 복구로 실제 동작한다.

### 시간표 (`/todayclass/`)
- 학교 선택기(공통). 학년·반(·학과) 칸은 인라인으로 두고, `change`가 일어나면 바로 조회한다(조회 버튼 제거).
- 세그먼트 [일간 | 주간]. 일간은 교시 괘선 목록, 주간은 월~금 격자이고 오늘 열에 형광펜을 칠한다. 모바일 주간은 가로 스크롤.

### 가이드·글·FAQ·사용법·개인정보
- 가이드 허브(`/blog/`)는 주제 3그룹(점수 계산 / 내신등급 / 대학 학점)을 **정적 마크업**으로 만든다.
- 글: `← 계산 가이드` 링크, h1, 요약, 날짜, 형광펜 박스 리드, 섹션(제목에 "공식"이 들어가면 노트 박스), CTA 버튼, 이어서 볼 글, FAQ 아코디언. `scripts/rebuild-guides.mjs` 템플릿을 바꿔 8개 글을 다시 생성하고, 손으로 쓴 2개 글(`grade-calculation`, `target-exam-score`)은 같은 구조로 직접 고친다.
- 사용법(`/guide/`): 지금은 없는 기능(과목 등록·계산 기록·그래프·AI)을 설명하고 있다. 새 UI 기준 사용법으로 내용을 다시 쓴다.
- 개인정보: 마크업만 새 셸로 바꾸고 법적 문구는 그대로 둔다.

### `<head>` 공통 변경
- `theme-color`: 라이트 `#FAF7F0`, 다크 `#14161D`(`media` 속성으로 구분).
- Pretendard `preconnect`와 스타일시트 링크.
- `manifest.json`의 `background_color`와 `theme_color`를 새 색으로 바꾼다.
- 그 밖의 메타, GTM, AdSense는 한 글자도 바꾸지 않는다.

## 보안

외부 API 값(학교명, 급식 메뉴, 시간표 과목)과 localStorage에서 복원한 값(과목명 등)은 `textContent`나 `.value`로만 넣는다. 기존의 `innerHTML` 템플릿 보간은 없앤다.

## 테스트와 검증

- `npm test`(메타·JSON-LD·sitemap)와 `npm run test:seo`는 100/100을 유지한다.
- 각 계산기 페이지의 순수 함수는 프로젝트 관례대로 `console.assert` 자체 점검을 둔다. 대상: 최종점수·등급·다음 등급 거리, 필요 점수 올림, 석차 등급, GPA와 등급 매핑, 환산.
- 브라우저 검증: 로컬 서버를 띄우고 모바일 390×844와 데스크톱 1440×900, 라이트·다크에서 페이지 7개 이상을 조작한다. 콘솔 assert 실패가 0이어야 하고, 스크린샷을 남긴다.
- 확인할 흐름:
  1. 수행·지필: 점수 입력 중 결과가 실시간으로 바뀌고 미니 결과가 뜨는지.
  2. 목표점수: 불가능과 달성 상태.
  3. 내신: 잘못된 석차를 넣으면 인라인 오류가 뜨는지.
  4. 학점: P만 있을 때.
  5. 새로고침 후 값이 유지되는지.
  6. 초기화가 두 번 눌러야 실행되는지.
