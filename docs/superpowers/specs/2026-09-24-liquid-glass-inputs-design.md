# 직관적인 입력 + 애플식 리퀴드 글래스 — 설계

## 배경

사용자 피드백(미니멀 도구 배포 뒤):
- 개인정보처리방침에서 애드핏과 좋아요/싫어요 문구를 지운다.
- 반영비율 빠른 선택을 없앤다.
- 색감과 모양 때문에 어디에 무엇을 입력하는지 직관적이지 않다. 최적화는 맡긴다.
- 휴대폰에 맞게 화면을 재구성해 쓰기 편하게 한다.
- 원하는 리퀴드 글래스가 아니다. 비교 이미지에서 **A. 애플 iOS 26 스타일**을 골랐고, 배포는 **검증 후 바로 배포**를 골랐다.

진단:
- 입력칸이 밑줄뿐이라 글자처럼 보인다. 선택 상태도 형광펜 밑줄이라 눌리는 것처럼 보이지 않는다.
- 휴대폰에서 결과 카드가 맨 위에 있어 첫 입력칸이 화면 아래(약 700px)에서 시작한다.
- 유리가 62% 불투명한 종이색이고 뒤가 단색이라 흰 상자로만 보인다.

## 원칙

- **입력칸은 입력칸처럼.** 흰 상자(52px, 모서리 13px, 1.5px 테두리), 위에 진한 라벨, 포커스는 파란 테두리와 링, 오류는 빨간 테두리.
- **색의 역할을 나눈다.** 파랑은 누르거나 고르는 것, 형광펜은 결과 강조, 초록은 맞음, 빨강은 문제다. 배경은 중립 회백색이다.
- **모양을 통일한다.** 입력은 사각 상자, 고르기는 알약 세그먼트(흰 알약이 선택), 개수는 동그란 −/+ 버튼, 추가는 점선 상자 버튼이다.
- **입력 순서를 보여 준다.** 입력 구역 제목 앞에 파란 번호 원(1, 2, 3)을 둔다. 참고용 구역에는 붙이지 않는다.
- **휴대폰은 입력 먼저.** 제목(과 초기화) → 입력 → 결과 카드 → 설명 순서다. 결과는 화면 아래에 떠 있는 유리 결과 바에 실시간으로 보이고, 누르면 결과 카드로 이동한다. 결과 카드의 큰 숫자가 보일 때는 결과 바를 숨긴다.
- **데스크톱은 2단.** 왼쪽은 입력, 오른쪽은 결과 카드를 sticky로 둔다. DOM 순서는 입력 → 결과로 바꿔 화면과 읽기 순서를 맞춘다.
- 기능, URL, SEO 메타, 저장 키, 롤링·도장·축하 모션은 유지한다.

## 리퀴드 글래스 (A)

- **적용 대상:** 떠 있는 상단 캡슐, 도구 메뉴 팝오버, 하단 결과 바, 되돌리기 알림. 본문 카드는 유리로 만들지 않는다.
- **재질:**
  - 옅은 틴트 위에 약한 흐림(캡슐 8px, 결과 바 6px), 채도 1.8, 밝기 1.05.
  - 팝오버와 알림은 글이 많아서 더 뿌옇게 한다.
- **굴절:**
  - 가장자리 띠에서 뒤 화면이 휘어 보이게 SVG `feDisplacementMap`을 `backdrop-filter`에 건다.
  - 크로미움(크롬·엣지·삼성 인터넷)에서만 켜고, 나머지 브라우저는 흐림 유리만 쓴다.
  - 요소 크기에 맞춘 변위 맵을 JS로 만들고 `ResizeObserver`로 갱신한다.
- **빛:** 위·왼쪽 안쪽에 밝은 반사 테두리, 아래·오른쪽에 약한 테두리, 비스듬한 윤광, 부드러운 그림자를 준다. 다크 모드는 값을 따로 둔다.
- **접근성:** `prefers-reduced-transparency`이면 불투명 표면으로, `backdrop-filter` 미지원이면 거의 불투명한 틴트로 대신한다.

## 콘텐츠

- **개인정보처리방침:**
  - 1항에서 "좋아요/싫어요 선택 여부"를 뺀다.
  - 3항(좋아요/싫어요 집계)을 삭제한다.
  - 광고 항은 실제로 쓰는 구글 애드센스 기준으로 고쳐 쓰고, 애드핏 문구는 삭제한다. 쿠키 안내는 유지한다.
  - 항 번호를 다시 매기고 시행일자를 2026-09-24로 바꾼다.
- **수행·지필:** 반영비율 빠른 선택 카드와 코드를 삭제한다. `splitWeights`는 다른 곳에서 쓰지 않으므로 함수와 테스트를 함께 지운다.
- **사용법:** 결과가 상단바가 아니라 아래 결과 바에 뜬다는 설명으로 고친다.
- **결과 바 문구:** 라벨은 결과 카드 라벨을 쓰고, 값은 접두어 없이 쓴다(예: "필요 97.5점" → "97.5점"). "값 · 등급"이면 등급을 형광펜 배지로 보여 준다.

## 검증

- `npm test`, SEO 100/100.
- 기존 QA 스위트를 새 마크업에 맞게 갱신한다. 미니 결과는 결과 바로 바뀐다.
- 새로 확인할 것:
  - 결과 바가 휴대폰에서 스크롤 위치에 따라 보이고 숨는지, 누르면 결과 카드로 가는지, 데스크톱에서는 안 뜨는지
  - 캡슐·결과 바에 굴절 필터가 걸리는지(크로미움), 필터 크기가 요소 크기와 같은지
  - 입력칸 테두리 대비
  - 320·360·390·1440 라이트·다크 스크린샷, 가로 스크롤 없음, 콘솔 오류 0
- 배포: main에 push하고 Pages 빌드가 끝나면 라이브 해시와 스모크 테스트를 확인한다. CSS/JS를 바꾸므로 `?v=`를 올린다.

## 추가 요청(작업 중 변경): 애플 디자인 시스템과 하단 단일 바

사용자 요청:
- 형광펜 느낌을 모두 뺀다.
- 로고와 사이트 전체를 `DESIGN-apple.md`(apple.com 디자인 분석)에 맞춰 재구성한다. 특히 라이트 모드를 신경 쓴다.
- 휴대폰에서는 내비게이션 바를 아래에 두고, 스크롤하면 작아졌다 커지게 한다. 위아래 두 개였던 바는 하나로 합친다.

적용:
- **색**
  - 라이트: 캔버스는 흰색, 페이지 배경은 파치먼트 #f5f5f7, 글자는 잉크 #1d1d1f, 보조 글자는 #6e6e73, 헤어라인은 #e0e0e0·#d2d2d7이다.
  - 조작 색은 액션 블루 #0066cc 하나다. 포커스는 #0071e3을 쓴다.
  - 형광 강조색(#DDF55A)과 그라데이션은 없앤다.
  - 초록·빨강은 합계 맞음과 오류 표시에만 쓴다.
- **글꼴**
  - 스택: `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Pretendard Variable", …`. 애플 기기에서는 SF Pro와 SD 고딕 Neo, 그 밖에서는 Inter 기반인 Pretendard가 나온다.
  - 본문은 17px/400, 제목은 600이고 자간을 음수로 준다. 굵기는 400·600·700만 쓴다.
- **모양**
  - 기본 버튼은 파란 알약, 보조 버튼은 파란 테두리 알약이다.
  - 입력칸은 11px 모서리와 1px #86868b 테두리를 쓰고, 포커스는 2px 파랑이다.
  - 선택지는 알약 칩이고, 선택되면 2px 파란 테두리가 된다.
  - 원형 회색 칩 버튼(−/+, ×, 날짜 이동)을 쓴다.
  - 카드는 흰색, 18px 모서리, 헤어라인이며 그림자는 없다.
- **등급 표시:** 형광 배지 대신 잉크 원 테두리에 글자를 넣는다. 축하는 애플 시스템 색 종이 조각과 잉크 알약 배지로 한다.
- **내비게이션**
  - 데스크톱은 상단에 반투명 유리 바 하나다(라이트는 파치먼트 80%, 다크는 검정 80%, `saturate(180%) blur(20px)`, 헤어라인, 그림자 없음). 로고, 도구 링크, 테마 버튼을 담는다.
  - 휴대폰은 iOS 26 사파리처럼 하단에 떠 있는 유리 바 하나다. 도구 메뉴 버튼, 가운데의 현재 도구명 또는 실시간 결과, 테마 버튼을 담는다.
  - 휴대폰 바는 아래로 스크롤하거나 입력 중이면 작은 알약(결과나 도구명만)이 되고, 위로 스크롤하거나 맨 위면 다시 커진다. 작은 상태에서 누르면 커진다.
  - 도구 메뉴는 바 위로 열리는 유리 시트다.
- **로고:** 잉크 스퀘어클에 흰 "A+"를 넣는다. 파비콘·앱 아이콘·공유 이미지를 형광 없이 다시 만든다.
